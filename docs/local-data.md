# 本地数据、备份和边界

## 存储

启动日志显示实际目录，默认见 README。SQLite 使用外键、事务、递增 revision、项目内事件序号及唯一活动 run 约束；单进程写入排队。数据库使用 DELETE 日志模式，不使用 WAL。schemaVersion 使用 SQLite user_version，目前为 4（完成交付记录独立于项目生命周期）。

迁移前对已有旧版数据库执行 SQLite VACUUM INTO，生成同目录 `backup-before-vN-时间.sqlite`；DDL 在事务内执行，失败回滚，不清空原库。不支持读取比程序更新的 schemaVersion。

文件按随机 snapshot ID 保存，不按用户文件名拼磁盘路径。SHA-256 校验在暂存、导入及解析读取时执行；快照只读，应用不修改用户原件。浏览器仅传输用户选定的文件字节，不传服务器可打开的任意源路径。一次性选择 token 绑定项目，十分钟过期。待导入总量同样限制为 30 份 / 100 MiB；服务重启清理其过期会话暂存，不删除正式快照。

解析结果和原文存入数据库，可能包含私人材料。不自动同步、不做遥测。第三阶段在用户配置并主动开始任务后，将选定范围的文字、目标、要求及文件名称发送到指定模型。供应商的数据处理受其服务条款约束。

## 备份与恢复

1. 在运行终端 Ctrl+C，等待服务完全退出。
2. 将整个数据目录复制到一个新的备份目录，包含 SQLite 与 snapshots；不要只备份数据库或只备份副本。
3. 恢复时先停止服务，保留原目录，使用 `SHOUWEI_DATA_DIR` 指向备份副本进行检查。不要覆盖唯一一份数据。

同一目录只允许一个本机服务，`.server.lock` 记录进程号而不记录材料。正常退出会清除锁；断电或强制 kill 可能保留锁，此时先读取锁中的 PID 并确认该进程确实已退出，再只移除该目录的 `.server.lock` 后重新启动。不要在另一个服务仍运行时删除锁。重启会将中断的读取任务改为 interrupted，并允许重新读取。

网页 `/local/storage` 提供确认删除真实项目和诊断预览。删除项目保留原件、完成的冻结记录及交付包/报告，并保留迁移备份；清理失败在启动时继续。没有一键整库备份或彻底擦除按钮。示例「清空」仍只影响示例。

快照校验失败时，重新选择未损坏的原件导入。去重前会核验已有快照；坏副本保留历史，原件另存新快照，可选更新同一材料的新版本。该操作仍受项目容量限制，满额时需先备份并另建项目；当前不提供直接修补或删除旧快照的界面。

## 解析限制

- 每个解析子进程最多 15 秒、V8 old space 256 MiB，超时杀死并等进程关闭；同时最多两个解析任务。该限制不是操作系统级完整内存沙箱。
- 文件最多 20 MiB；DOCX ZIP 展开声明体积最多 50 MiB、最多 2000 个条目，拒绝路径穿越和宏部件。只展开所需正文 XML，外部引用不访问。
- 每份文档最多 2000 个定位块，每块最多 6000 码点；当前项目已解析文本合计最多 200000 码点，超出返回明确 coverage gap。不会把保留的前半段标成完整覆盖。
- TXT/MD 以真实行号定位；DOCX 以正文段落或表格/行/列定位，不猜页码；PDF 保留实际页码与文字片段，不提供假矩形高亮。
- DOCX 单元格保留段落换行；嵌套表格、图片、修订、批注、页眉页脚、嵌入内容等提示未覆盖。PDF 始终提示阅读顺序风险；扫描页无 OCR，加密文件不接收密码。
- 预览按纯文本显示。文字读取与语义检查分开，模型结果通过程序引文验证后展示；最终交付结论由程序校验，不由模型直接放行。

## 第三阶段检查记录

workflows 表保存要求版本、选定范围、运行模型参数（不含 Key）、检查点、事实、候选拒绝原因、结果、人工决策和提取缓存。相同输入摘要的完整提取批次可以复用，跨文件判断每次重跑。模型中途失败不复用未提交输出；启动后将中断任务标为 interrupted。

普通连接参数保存于 model-settings.json；默认 Key 仅服务内存，明确选择时引用系统 Keychain。不写入 SQLite 或浏览器持久化存储。单次 Harness 运行目录在退出确认后删除；未确认退出时保留诊断现场并阻止新检查，需重启服务。数据库和备份仍可能包含材料正文，请按私人文件保管。

## 第四阶段交付记录

deliveries 表保存交付时的冻结项目、检查、要求、人工理由和附件摘要。产物位于 `exports/<交付ID>/交付包.zip` 和同目录独立 `检查报告.html`。准备页实时计算不保存记录，点击预览才保存；后台生成不会调用模型。复制完整数据目录备份时也应包含 exports。

所有业务修改和导出共用写入队列，生成期间冻结输入；哈希核验和临时目录原子完成后才记 completed。中断的 writing/verifying 记录在启动时改为 failed，历史不伪造成功。未完成记录不显示为交付历史。

下载只读取记录绑定的受限文件并再次校验 SHA256。文件被移动、删除或改变时，旧交付记录仍保留。取消浏览器保存与服务端生成状态独立，不能据 completed 推断客户端已保存。

## 第五阶段删除与诊断

删除在共用队列内检查 revision 和活动任务，先写受限清理记录，再事务删除工作数据；记录用独占临时文件、sync 与 rename 完成，数据库失败回滚且不删除快照。完成交付表解除项目外键，冻结产物可继续下载。事务成功后的磁盘清理失败返回 cleanupPending，下一次启动只重试记录内随机快照 ID，不递归删除用户任意源路径。恢复逐条隔离失败；截断或非法记录保留为 `.invalid-*`，不凭猜测删除材料，也不阻断整个应用启动。中断导出的受限临时目录在启动清理，已完成目录与无关目录保留。

新的 Harness `model-runtime/call-*` 目录在运行前写入受限 owner.json，绑定项目、运行、目录名和服务 PID。启动或删除项目时，只有确认所有者已退出、没有运行时进程引用目录、路径与归属均验证通过的目录才可清理。活进程或无法确认的进程不会被杀死，并阻止新的模型调用；其他项目、符号链接目标及旧版无归属目录保留。诊断只报告 cleanupPending 等安全状态，设置页提示人工检查。旧版无归属残留不能保证自动清除；先确认服务和相关进程均已退出，再由用户检查，不提供猜测删除路径。

系统 Keychain 不包含在普通数据目录备份里；恢复到别的机器后需要重新配置 Key。诊断不含数据目录或模型地址，只含白名单版本/枚举/计数。备份文件与冻结交付报告仍需私人保管。
